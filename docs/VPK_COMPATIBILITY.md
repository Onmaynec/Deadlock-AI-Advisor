# v0.7.0 — VPK Compatibility & Packaging

## Цель релиза

Устранить главный пробел v0.1–v0.6: раньше тестировались отдельно ресурсы и упаковщик, но **полная сборка мода** не проходила через настоящий путь \`tools/build.cjs\` в тестовой установке. Новый тест формирует временный каталог игры, три скомпилированных ресурса и реальный однoфайловый Source 2 VPK, затем запускает сборку и установку через тот же код, что используется на Windows.

**Не путать:** виртуальная установка и успешное чтение скомпилированных блоков не означают, что текущий клиент Deadlock способен выполнить этот Panorama-скрипт. Такой тест можно подтвердить только на ПК с установленной игрой.

## Что изменилось

- **Интеграционный тест полного пути:** \`npm run test:build\`, либо все тесты через \`npm run check\`. Проверка включает компоновку всех модулей HUD, Source 2 resource metadata, byte-for-byte VPK roundtrip, установку, обновление, удаление, чужой слот, испорченную сборку и подозрительные пути в записи установки.
- **Проверка игрового шаблона:** сборщик использует только Panorama-script template с \`DATA\` и \`RED2\`. Он не выбирает случайный ресурс с неправильным форматом. Для HUD и CSS обязательны корректные скомпилированные шаблоны из текущего \`pak01_dir.vpk\`.
- **Структурная проверка \`hud.xml\`:** при удалении/дублировании ключевых контейнеров сборка прекращается. Исключён повторный инъект скрипта. Отсутствующие ресурсы ведут к понятной ошибке.
- **Привязка кеша:** \`cache/stock_hud_meta.json\` хранит хеш каталога оригинального VPK и скачанного \`hud.xml\`. Кеш можно использовать повторно только при совпадении SHA-256. Режим \`--offline\` запрещает использовать неподтверждённый кеш.
- **Проверяемый результат:** после упаковки все три ресурса извлекаются и сравниваются побайтно. Только затем VPK публикуется в \`out\`.
- **Контроль сборки:** \`out/build_manifest.json\` хранит SHA-256 базового VPK, итогового файла, каталога, разметки и выбранный шаблон скрипта. Абсолютный путь к установленной игре в manifest **не записывается**.
- **Безопасная установка:** копирование в \`.daa-next\`, проверка хеша, резервное переименование старого файла, восстановление старой версии при ошибке сохранения нового файла; чужой слот запрещён. До проверки входных данных \`gameinfo.gi\` не изменяется.
- **Безопасное удаление:** хеш установленного VPK должен совпасть с записанным. Пути из локального \`installed.json\` проверяются, чтобы повреждённая запись не позволяла удалить посторонний файл.
- **Расширенная диагностика:** \`npm run doctor\` теперь сверяет хеши manifest, текущего базового VPK, кеша и установленного мода.

## Важное ограничение SteamTracking

Для исходной разметки используется публичный \`SteamTracking/GameTracking-Deadlock\`:

https://github.com/SteamTracking/GameTracking-Deadlock/blob/master/game/citadel/pak01_dir/panorama/layout/hud.xml

Это **не версия разметки, извлечённая локально из конкретного VPK пользователя**. Новый мета-кеш фиксирует, с какой установленной игрой она была использована при сборке, но **не доказывает**, что эта версия разметки точно соответствует тому же build игры. Поэтому после крупного патча сравнение и проверка результата непосредственно в игре обязательны.

Возможен конфликт с любым другим модом, заменяющим \`panorama/layout/hud.vxml_c\`, даже если файлы лежат в разных VPK-слотах. Для этих конфликтов нужно выбрать один совместимый HUD или выполнить ручное объединение модов.

## Порядок проверки на Windows

В папке репозитория, Node.js 22.2+:

~~~powershell
git pull
npm run check
npm run test:build
npm run sync
npm run doctor
npm run install-mod
npm run doctor
~~~

При успешной установке смотри \`out/build_manifest.json\`, а также \`npm run doctor -- --json\` для структурированного отчёта. Если базовый VPK обновился после установки, doctor покажет предупреждение. Пересобирай мод после патча.

Для полностью локальной повторной сборки **только после** одной подтверждённой онлайн-сборки:

~~~powershell
node tools/build.cjs --offline
~~~

Если игры или кеша нет, офлайн-команда должна завершиться ошибкой, а не использовать устаревшую разметку.

### Проверка в Deadlock

1. Закрой Deadlock перед установкой или обновлением.
2. Установи мод. Запусти приватный тестовый матч и открой магазин.
3. Проверь появление нативной панели, горячую клавишу, отсутствие ошибок Panorama в консоли.
4. Протестируй изменение душ, автоопределение героев, вкладку покупок и маршрут закупок.
5. Если клиент не запускается или HUD исчез, выполни \`npm run uninstall-mod\`, проверь и восстанови игровые файлы стандартными средствами Steam; исследуй \`gameinfo.gi\` и резервную копию \`cache/gameinfo.gi.bak\`.
6. Перед отправкой логов удали личные сведения. Достаточно ошибочного ресурса, версии игры, отчёта doctor и версии Node.js.

**Статус:** автоматический offline build/install test реализован; действительный клиент Deadlock здесь не запущен. Бинарный релиз, гарантированно совместимый с текущим патчем, не заявляется. Генеративная нейросеть и автоматическое чтение инвентаря/владельцев покупок всё ещё не подключены.
